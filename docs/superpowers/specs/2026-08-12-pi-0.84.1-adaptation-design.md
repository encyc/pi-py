# pi v0.84.1 适配设计

> 破例同步 patch：按 `SYNC.md` 现行策略只追上游 `0.x.0`(minor)；
> 本轮由用户明确点名 `0.84.1`，属于跨 minor（0.83.0 → 0.84.0）并在其上叠加
> `0.84.1` patch 的破例同步。各包 `PORTING.md` 的「v0.84.1 同步说明」小节
> 均会标注「破例同步 patch」。

## 背景

`pi-py` 当前对齐 `earendil-works/pi@v0.83.0`（sync commit `8e8ec34`）。上游
`v0.83.0...v0.84.1` 区间共 **371 个 commit**（v0.83.0 commit `845d6ff` 是
v0.84.1 commit `53fa77c` 的直接祖先）。该区间是一次体量很大的 release，主线
工作流包括：

- **harness v2**：`agent-harness` 重写、reducer、telemetry span、JSONL codec、
  session 仓库化、conformance 测试矩阵；
- **新包**：`packages/telemetry`、`packages/protocol`、`packages/client`
  （runtime-neutral session client / Unix socket transport）、`packages/evals`；
- **包重命名**：`packages/storage` → `packages/session-backends`（且其 `src/`
  在 v0.84.1 为空——SQLite/JSONL 后端已下沉进 `agent` harness 内部）；
- **server 重写**：移除 legacy radius/supervisor，改为 composable protocol
  server + Unix transport；
- **pi-ai**：泛型采样参数、`thinking_token_budget`、无 `finish_reason` 流的
  支持、Anthropic 初始块内容保留、Baseten / Qwen Token Plan Individual 新
  provider、OpenAI Responses deferred/background 模式、telemetry context；
- **agent**：`shouldStopAfterTurn` 暴露到 `Agent`、blocked tool call 可终止、
  运行中 `reset()` 拒绝。

`pi-py` 定位为精简 Python SDK：保留 `pi-ai`、agent runtime、编码工具 SDK、
SQLite storage、server，**不复刻** CLI/TUI、OAuth、扩展系统、TypeBox、
Google/Mistral/Bedrock provider、图片 provider、动态模型目录。因此本轮 371
个 commit 中绝大多数（harness v2 内部、telemetry/protocol/client 包、TUI、
evals、coding-agent CLI/modes、session 仓库化、新 provider）落在既定裁剪范围
之外，仅移植落入当前精简 runtime 的行为变更。

### 信息来源说明

- 上游 tag / commit 区间通过 `git fetch`（`--no-tags` + 临时 ref
  `refs/pi/*`，未污染本地 tag 命名空间）+ `git diff`/`git log` 取得，**权威**。
- `gh api` 与 `WebFetch` 访问 `api.github.com` / `github.com` 全程失败
  （`EOF` / `SSL_ERROR_SYSCALL` / `ECONNRESET`，间歇性可用），故 release
  notes / CHANGELOG 的用户可见摘要无法通过 Web 获取；本设计改以 commit 列表
  + 逐文件 diff 为准。

## 目标

- 将 OpenAI-compatible 适配器对齐到 v0.84.1：泛型 `samplingParams`、
  `thinking_token_budget`、以及无 `finish_reason` 流的终止推断。
- Anthropic 适配器保留 `content_block_start` 携带的初始文本/思考内容。
- agent runtime 对齐三处行为：`shouldStopAfterTurn` 公共钩子、blocked tool
  call 可终止、运行中 `reset()` 抛错。
- 五个包及同步元数据统一升级到 `0.84.1`，workspace 内部依赖收口到
  `>=0.84.1,<0.85`。
- 用单元测试、静态检查以及（若本机有 key）DeepSeek + OpenAI 兼容端点真实验证
  无 `stop_reason` 退化。

## 非目标 / 裁剪项

下列上游能力本轮**不移植**（与既有裁剪边界一致）：

- **deferred / background 模式**：`StopReason "deferred"`、`DeferredHandle`、
  `AssistantMessage.deferred`、`done` 事件的 `deferred` reason、
  `fetchDeferred`/`cancelDeferred`、`SimpleStreamOptions.deferred`。这是
  OpenAI Responses 专属的异步/后台响应能力，本项目明确不移植 OpenAI Responses。
- **telemetry**：`TelemetryContext`、`ProviderRequestOptions.telemetryContext`
  及 `packages/telemetry` 包。
- **新 provider**：Baseten、Qwen Token Plan Individual。`KnownProvider` 字面量
  补齐以保持类型对齐，但不注册 provider 实现/模型（与「精简 provider 集」一致）。
- **`baseten` thinkingFormat / `chatTemplateArgs`**：随 Baseten provider 一并
  裁剪。
- **error-body 的 `isPlainNonEmptyObject`**：针对 AWS SDK v3 wrapper 对象的修
  补；本 Python 端 `_format_error` 走 `APIStatusError.body/response.text`，不
  存在该 bug，不适用。
- **harness v2 全部内部重构**：reducer、telemetry、JSONL codec、session 仓库
  化、conformance 矩阵、`session-backends` 重命名（其 `src/` 在 v0.84.1 为
  空）。本项目 `pi-agent-core` 维护精简 harness，不追逐 v2 重写。
- **`packages/protocol` / `packages/client` / `packages/evals`**：整包不移植。
- **server 重写**：上游 composable protocol server + Unix transport 依赖
  `protocol`/`client`/`telemetry` 包，本端 `pi-server` 为精简 RPC/supervisor，
  维持现状。
- **coding-agent CLI/TUI/modes/extensions/dynamic-catalog**：工具层上游改动
  （Windows 路径、`*SystemPromptContribution` 结构、model-runtime/catalog）不
  映射到本端精简 `tools.py`。
- **`models.generated.ts` / 动态模型目录**：维持精简硬编码模型集。
- **`StreamOptions` 结构重构**（抽取 `ProviderRequestOptions` 基类）：上游是
  TS interface 重组，Python 端 `StreamOptions` 已含全部所需字段，无需复刻继承
  层级；只新增 `samplingParams` 字段。

### 待确认（跳过，不臆测）

- `api/lazy.ts`、`api/openai-responses-shared.ts`、`api/openai-codex-responses.ts`
  等未移植 API 模块的改动，整模块在裁剪范围，未逐行判定。
- `models.ts`（+451）几乎全是动态模型目录数据，非运行时逻辑，跳过。

## pi-ai 设计

### `types.py`

- `StreamOptions` 增加 `sampling_params: dict[str, Any] | None`
  （别名 `samplingParams`）。请求级采样参数，由 OpenAI-compatible 适配器合并进
  请求体（覆盖具名字段），其他 API 忽略。
- `Model` 增加 `sampling_params: dict[str, Any] | None`（别名 `samplingParams`）。
  模型级默认采样参数；请求级按 key 覆盖模型级。
- `KnownProvider` 补 `"baseten"`、`"qwen-token-plan-individual"`（仅类型对齐，
  不注册实现）。
- **不**新增 `StopReason "deferred"` / `DeferredHandle` / `AssistantMessage.deferred`
  （deferred 裁剪）。
- `compat` 仍是宽松 `dict[str, Any]`，故 `supportsFinishReason` /
  `supportsThinkingTokenBudget` 等 compat 键无需改类型，provider 侧读 dict。

### `providers/openai_provider.py`

1. **无 `finish_reason` 流的终止推断**（`2c30412 fix(ai): support streams without
   finish reasons`）：读 `compat.get("supportsFinishReason", True)`。当为
   `False` 且流结束时未见 `finish_reason`，按内容推断 `toolUse`（含工具调用）或
   `stop`；仅当 `supportsFinishReason` 为真却仍缺 `finish_reason`、或停在
   `pending` 时才抛 `Stream ended without finish_reason`。默认值 `True` 保持既有
   行为不变。
2. **泛型采样参数**（`25a2c8d feat: support generic sampling parameters`）：构建
   请求体末尾先 `params.update(model.sampling_params)`，再
   `params.update(options.sampling_params)`，使自定义键（`top_p`/`top_k`/
   `min_p`/`repetition_penalty` 等）覆盖具名字段。
3. **`thinking_token_budget`**（`d07889d feat(ai): support thinking_token_budget`）：
   当 `compat.supportsThinkingTokenBudget` 为真、有 reasoning effort 且模型
   `reasoning=True` 时，按 level（`minimal:1024/low:2048/medium:8192/high:16384`，
   被 `options.thinking_budgets` 覆盖）算预算，上限 `max_tokens - MIN_ANSWER_TOKENS`
   （`MIN_ANSWER_TOKENS=1024`），正值写入顶层 `thinking_token_budget`。防止
   vLLM 端推理耗尽整个响应导致无答案/无工具调用（与「无 stop_reason 退化」目标
   直接相关）。

### `providers/anthropic_provider.py`

- **保留初始块内容**（`59ad3dea fix(ai): preserve Anthropic initial stream block
  content`）：`content_block_start` 的 `text`/`thinking` 块用
  `event.content_block.text ?? ""`、`thinking ?? ""`、`signature ?? ""` 初始化，
  而非硬编码空串。某些响应在 start 事件即携带内容。

## pi-agent-core 设计

### `agent_loop.py`

1. **blocked tool call 可终止**（`1eb988c feat(agent): allow blocked tool calls to
   terminate`）：`_execute_single` 中 `before_tool_call` 返回 `block=True` 时，
   终止标志取 `bool(before.get("terminate"))`（原先恒为 `False`）。
2. **`should_stop_after_turn` 接线**（`0f5286d feat(agent): expose shouldStopAfterTurn`）：
   `_run_loop` 内层每轮 `TurnEndEvent` 之后、再次拉取 steering 之前，若
   `config.should_stop_after_turn` 存在，以
   `{message, tool_results, context, new_messages}` 调用；返回真则发
   `AgentEndEvent` 并退出。（`AgentLoopConfig.should_stop_after_turn` 字段此前已
   存在但未被调用。）

### `agent.py`

1. **运行中 `reset()` 拒绝**（`1532c99 fix(agent): reject reset during active
   runs`）：`reset()` 在 `_active_run` 非空时抛 `RuntimeError`。
2. **暴露 `should_stop_after_turn`**：`AgentOptions` 与 `Agent` 新增
   `should_stop_after_turn`，`_create_loop_config` 将其接入 `AgentLoopConfig`。

## pi-storage-sqlite / pi-coding-agent / pi-server

无运行时改动，仅版本号与文档同步：

- `pi-storage-sqlite`：上游 SQLite 查询优化（`ae1e410`）、SQL 模板查询
  （`055ecce`）、分支缓存等均位于 `agent` harness v2 session 内部；
  `session-backends/src/` 在 v0.84.1 为空。本端 `storage.py` 为独立精简实现，
  schema/查询结构不同，不映射。
- `pi-coding-agent`：上游工具改动为 Windows 路径与 `*SystemPromptContribution`
  结构，不映射到精简 `tools.py`；CLI/TUI/modes/extensions 维持裁剪。
- `pi-server`：上游 server 重写依赖未移植的 `protocol`/`client`/`telemetry`，
  本端精简 RPC/supervisor 维持现状。

## 测试设计

### 单元测试

`pi-ai` 增补/更新回归：

- `samplingParams`（请求级 + 模型级）合并进 OpenAI 请求体，且覆盖具名字段；
- OpenAI 流：模型 `compat.supportsFinishReason=False` 且无 `finish_reason` 时，
  推断 `stop`/`toolUse` 而非报错；默认（`True`）仍报错；
- OpenAI 流：`compat.supportsThinkingTokenBudget=True` + reasoning 时注入
  `thinking_token_budget`，且不超过 `max_tokens - 1024`；
- Anthropic 流：`content_block_start` 携带的初始 text/thinking/signature 被保留。

`pi-agent-core` 增补：

- `before_tool_call` 返回 `block + terminate` 时循环终止；
- `should_stop_after_turn` 返回真时发 `agent_end` 退出；
- 运行中 `reset()` 抛错。

五个包 smoke tests 断言 `0.84.1` 与 `earendil-works/pi@v0.84.1`。
